# ③ 离线研究简报与受控比较

教师未提供专用包。本部分采用自建摘要卡、规则控制器及结构校验器；不是教师 fixture，也没有执行 LLM 推理。是否满足教师认可 Agent 工具的要求仍需教师认定。

## 重跑与文件
从仓库根目录执行 `node src/agent/run-agent.mjs`。需要 Node.js 18+，无第三方依赖、GPU、API 或运行时网络。

根目录 final-brief.md、trajectory.jsonl、tool-results.jsonl、provenance.json、error-note.md 对应六步完成组。两组原始输出保存在 runs/max_steps_3 和 runs/max_steps_6，evaluation.csv 保留全部比较结果。独立校验命令为 `node src/agent/validator.mjs src/agent/runs/max_steps_6`。

## 两页以内分析
任务是搜索固定离线来源包、读取三个相关来源，生成关于偏好对齐中参考模型依赖的简报。来源包包括 DPO、ORPO、SimPO 三张 AI 辅助改写的中文摘要卡及一个无关操作备注。卡片保留原文链接与方法定位，但不是论文全文。文献筛选和摘要整理在实验前完成，不能算作实验中的自动阅读成果。

规则控制器根据 observation 决定下一动作：search → 三次 read_source → write_brief → validate。简报采用固定模板。每次真实工具调度记录 call_id、参数及完整返回值。provenance 保留来源、程序、contract、schema 与 validator 的 SHA-256。

| 设置 | 实际 calls | 已读来源 | 结构评分 | final-state | 预算内校验 |
|---|---:|---:|---:|---|---|
| max_steps=3 | 3 | 2 | 1/5 | 失败 | 未执行 |
| max_steps=6 | 6 | 3 | 5/5 | 通过自建校验 | 已执行 |

唯一变因是 max_steps；任务、来源包、工具描述、控制器、validator 与 rubric 不变，两组从隔离的空输出状态开始。一次工具调用计一步，write_brief 与 validate 也计步；运行后的外部 audit 不算 Agent 调用。

五项各一分：搜索、读满三源、简报存在、引用得到已读卡片支持、篇幅及必要段落。这是本次自建诊断评分，并非教师评分权重的换算。

短预算组在 search、read S1、read S2 后耗尽预算，尚未读取 S3，也没有生成简报。失败发生在信息收集阶段，不是引用幻觉。最容易出错的是把外部 audit 当作预算内调用，或复用上次残留简报。程序分别保存 audit，并在重跑前清除该组已知输出以避免污染。

校验器检查来源读取记录、引用标记、原文链接及卡片命题的一致性。两个反例测试证明不存在的 S9 引用和缺失读取记录会被拒绝。runs/validator-tests 是刻意破坏的测试材料，不是第三个实验条件。校验器不判断任意自然语言的语义蕴含，也不保证摘要卡本身完全正确。

这套工具粒度按设计需要六次调用，因此结果主要反映预算是否足够，具有构造性，不能证明六步 Agent 普遍更智能。只有一个确定性任务，重复运行不产生独立样本，不做统计显著性推断。

下一测试应加入不同任务、干扰文档、缺失来源和工具错误，固定任务集后重新比较两种预算，并由人工复核原文命题。如果课程要求模型式 Agent，应替换为认可的模型控制器并重跑，不能只更改 provenance。

安全边界是本地白名单来源 ID 与固定输出文件；来源中的文字只作为数据，不执行其中指令。运行时无网络、API及语言模型，但前期文献核验使用过网络，不能声称整个作业从未联网。
